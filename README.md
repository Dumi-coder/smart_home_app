# Smart Home Monitoring & Control System

A Flutter + Firebase mobile application for monitoring and controlling smart home devices across multiple floor plans, with backend-driven safety cutoffs and a companion hardware simulator.

## Tech Stack

- **Frontend**: Flutter (Dart)
- **Backend / Database**: Firebase Cloud Firestore
- **Auth**: Firebase Authentication
- **Safety automation**: Firebase Cloud Functions (scheduled + triggered)
- **Push alerts**: Firebase Cloud Messaging
- **Hardware simulator**: Firebase Hosting (web dashboard)

## Firestore Schema

```
/floors/{floorId}
    name: string
    gridWidth: number
    gridHeight: number
    imageUrl: string

/floors/{floorId}/devices/{deviceId}
    type: "outlet" | "multiswitch" | "iron" | "bulb" | "camera"
    name: string
    x: number
    y: number
    status: "ON" | "OFF" | "ERROR" | "DISCONNECTED"

    # multiswitch only
    switches: [ { id, label, state } ]

    # iron only (safety-critical)
    maxOnDurationMinutes: number
    turnedOnAt: timestamp | null

    # bulb only (scheduled)
    scheduleStart: string   # e.g. "18:00"
    scheduleEnd: string     # e.g. "23:00"

    # camera only
    snapshotUrl: string

/usageLogs/{logId}
    deviceId: string
    floorId: string
    event: "ON" | "OFF" | "AUTO_CUTOFF"
    timestamp: timestamp

/alerts/{alertId}
    deviceId: string
    message: string
    timestamp: timestamp
    acknowledged: boolean
```

## Synchronization Mechanism

The app uses **Firestore's real-time listeners** (`snapshots()` streams) rather than manual polling or refresh buttons:

- Every screen that displays live data (`FloorsScreen`, `FloorDetailScreen`) wraps its UI in a `StreamBuilder` bound to a Firestore query.
- Writes from the mobile app (e.g. tapping a toggle switch) call `FirestoreService` methods, which update the relevant document.
- Any write — whether from this app, a teammate's device, the Firebase Console, or the backend Cloud Functions — triggers Firestore to push the updated document to every listening client automatically.
- This gives **bidirectional sync with no manual refresh logic**: the same stream serves both "my own change reflecting back" and "an external change appearing live."

Safety-critical devices (e.g. irons) are additionally monitored by a **scheduled Cloud Function** that runs periodically, checks `now - turnedOnAt` against `maxOnDurationMinutes`, and force-flips the device to `OFF` plus writes an entry to `/alerts` if the limit is breached — independent of whether the mobile app is even open.

---

## Floor Representation

Each floor is a document in `/floors`, with a `gridWidth` × `gridHeight` abstract grid. Devices store an `(x, y)` position within that grid, which is overlaid on an optional floor plan image (`imageUrl`) for visual context. This keeps device placement simple and decoupled from the actual pixel dimensions of any specific floor plan image.

---

## Hardware Simulator

A lightweight web dashboard (hosted via Firebase Hosting) listens to the same `/floors/{floorId}/devices` collections used by the mobile app. It visually represents each device's current state, standing in for physical hardware that the mobile client would otherwise control. Any state change made from the mobile app is reflected on the simulator within the normal Firestore propagation delay (typically well under a second), and vice versa.

## Setup Instructions

### Prerequisites
- Flutter SDK (stable channel)
- Android Studio with Flutter/Dart plugins
- A Firebase project with Firestore enabled
- Node.js (for Firebase CLI)

### Steps

```bash
# Clone the repo
git clone <your-repo-url>
cd smart_home_app

# Install Flutter dependencies
flutter pub get

# Install Firebase CLI + FlutterFire CLI (if not already installed)
npm install -g firebase-tools
dart pub global activate flutterfire_cli

# Log in and link to the shared Firebase project
firebase login
flutterfire configure
# → select the existing "SmartHome" project
# → select platforms: android, web

# Run the app
flutter run
```

> **Note:** All team members must use the *same* Firebase project (`smarthome-3508e`) so everyone reads/writes the same Firestore data. Do not create a new project when running `flutterfire configure`.

### Seeding sample data (development only)

The app includes a one-time seed button (cloud icon in the app bar) that populates Firestore with one example of each device type. Tap it once after first setup; avoid tapping it repeatedly to prevent duplicate documents.
